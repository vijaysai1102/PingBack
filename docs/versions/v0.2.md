# PingBack v0.2

## Goals & Summary

Make the existing Claude Code experience more dependable and configurable while preserving the local-only v0.1 architecture. v0.2 adds validated hierarchical notification settings, event-aware notification timing and sound behavior, stronger multi-session project association, and safe IDE/application focusing after a notification action.

## Scope & Requirements

- Preserve existing Windows and macOS support, Claude Code integration, local daemon, native notifications, sounds, and session tracking.
- Add backward-compatible hierarchical configuration for notification enablement, sound enablement and volume, plus per-event enablement and delay.
- Use default delays: question 5s, turn completion 3s, error 3s, and task completed 5s. Blocking user-action events notify immediately unless explicitly delayed.
- Validate configuration values and support `pingback config set <path> <value>` and `pingback config get <path>` for nested values.
- Produce concise native notifications that identify Claude Code, the event, and the associated project where available; honor sound settings without adding unnecessary audio dependencies.
- Improve event classification and ensure multiple Claude sessions retain their own project/session association.
- Add a platform-independent application-focus abstraction with Windows and macOS implementations. Detect and focus only a reliably associated IDE/application; notification delivery must succeed even when focus fails.
- Add a notification action, where the platform supports it, to return to the associated project. Do not focus a specific terminal or terminal tab.
- Improve setup and status output, including practical IDE discovery and concise multi-session/waiting summaries.
- Add coverage for configuration, event delays/sound, session association, application detection/focus, platform boundaries, and backward compatibility.
- Update README with v0.2 behavior, configuration, focusing limitations, privacy, and troubleshooting.

### Out of Scope

- No new agent integrations, Linux support, remote/cloud services, telemetry, mobile/web apps, third-party notification channels, or terminal-specific focusing.

## Technical Plan

### Audit result and preserved behavior

- `src/agents/claude/` uses Claude Code hooks and converts them to the core event model. The hook bridge has a short timeout and must remain non-blocking.
- `src/core/` validates IPC input, deduplicates events, routes them to `SessionManager`, and contains no Claude-specific logic.
- `src/sessions/` already keys state by Claude session ID, so concurrent sessions do not overwrite one another. v0.2 will extend this rather than introduce a global current session.
- `src/notifications/` formats native desktop notifications and plays generated WAV tones; it currently uses a flat desktop/sound config and immediately awaits delivery.
- `src/platform/` contains the Windows/macOS boundary for paths, IPC, and audio. Application discovery and focusing will join this boundary rather than add scattered operating-system checks.
- `src/cli/` already provides setup, status, and flat configuration commands. It will be extended in place.

### Feature implementation plan

1. **Backward-compatible hierarchical configuration**
   - Extend `src/config/config-manager.ts` to normalize the v0.2 notification tree: global enablement, sound enablement/volume, and per-event enablement/delay.
   - Read v0.1 `notifications.desktop` and boolean `notifications.sound` values as legacy inputs, migrate in memory to the new form, and retain safe defaults for absent or malformed settings.
   - Validate each write before persistence: booleans, a finite sound volume from 0 through 1, and non-negative finite delays. Invalid values will produce a focused CLI error and leave the current file unchanged.
   - Default to question 5s, turn completion 3s, error 3s, and task completed 5s. Blocking attention events (permission/input requests) will be modeled separately and notify immediately unless an explicit setting is introduced for them.

2. **Hierarchical configuration CLI**
   - Extend `src/cli/index.ts` and `src/cli/commands/config.ts` with `pingback config get <path>` plus nested `set` paths.
   - Keep `pingback config` as a concise full configuration view. `get notifications` will render the notification subtree, while `set` will support the documented sound and event-delay examples.
   - Support the existing flat key inputs as compatibility aliases where they do not conflict with the hierarchical schema, and show users the canonical v0.2 path.

3. **Event-aware notification scheduling**
   - Add a small, injectable scheduler near the notification policy/daemon boundary. It will accept the hook event immediately, schedule its notification for the configured delay, and keep the hook's fast IPC acknowledgement intact.
   - Key pending work by session and event type, cancel a stale pending attention notification when that session returns to `working` or ends, and preserve existing duplicate suppression before scheduling.
   - Keep routing/session persistence synchronous; only the user-facing delivery is delayed. This avoids five-second hook timeouts and stale notifications after a developer has already responded.
   - Confirm the final Claude notification mapping against current official Claude Code hook documentation before changing it. In particular, distinguish blocking permission/input signals, actual questions, normal turn completion, task completion, and failures rather than inferring from terminal output.

4. **Notification content and sound behavior**
   - Extend `src/notifications/notification-policy.ts` so notification enablement, event enablement, delay, project label, sound enabled state, and volume flow into a typed request.
   - Update `src/notifications/desktop-notification.ts` and `src/notifications/sound-service.ts` so every enabled v0.2 event receives a concise native notification and, by default, a short tone. Global sound disablement suppresses playback without suppressing the toast.
   - Pass configured volume through the existing platform sound abstraction using native capabilities only; no audio framework will be introduced. Event-specific sound overrides will be included only if they fit the final normalized schema without complicating the CLI.

5. **Safe IDE/application association and focusing**
   - Add a platform-independent application-focus contract (for application discovery, project-path association, and foregrounding) under a new `src/applications/` boundary, wired through the existing platform factory.
   - Add Windows and macOS implementations behind that contract. They will inspect available development applications only when needed, use a session's `cwd` to form a project association, and return no match when the association is not reliable.
   - Prioritize VS Code and Cursor as editors to foreground, not as additional coding-agent integrations. Other editors will be added only where detection is safe and testable.
   - Attach a resolved application association to the individual session (or safe session metadata) so simultaneous Claude sessions retain separate project targets. The association will be refreshed on meaningful session activity, not by aggressive background polling.
   - Keep focus best-effort: a failed or unsupported focus request is logged and never prevents notification delivery, never selects an unrelated app, and never focuses a terminal/tab.

6. **Notification activation**
   - Extend the notification request/service contract with a session-bound activation callback or identifier. Where the native notifier can report a click/action, it will invoke the focus service for that same session's associated application.
   - Validate node-notifier's current Windows/macOS action and click behavior before implementation. If a platform cannot expose a reliable action, clicking remains a harmless dismissal rather than guessing a target.

7. **Session, status, and setup improvements**
   - Preserve session-ID identity in `SessionManager`; extend its persisted model only with the minimal project/application association needed for focusing.
   - Refine `src/cli/status-view.ts` to show concise per-project multi-session state, waiting duration, active-session total, and attention total.
   - Extend `src/cli/commands/setup.ts` to report notification availability, sound availability, installed Claude integration, and non-fatal detection of supported editors. PingBack remains fully usable when no editor is found.

8. **Documentation, versioning, and tests**
   - Bump package/release documentation to v0.2 when implementation begins, and update `README.md` with the configuration tree, defaults, delays, focusing behavior, supported editors, privacy, troubleshooting, and terminal-focusing limitation.
   - Extend the existing Vitest suite rather than replace it: config parsing/migration/validation/persistence; scheduler delay/cancellation; notification/sound behavior; concurrent session-to-project association; platform focus detection/success/failure; CLI get/set/status/setup; and end-to-end event-to-notification behavior.
   - Run unit/integration checks after each major step. Perform real Windows and macOS notification/focus validation separately; automated cross-platform tests will mock platform commands but will not be presented as proof of native foregrounding.
