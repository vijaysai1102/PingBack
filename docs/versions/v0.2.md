# PingBack v0.2 — Multi-Agent Attention Layer

## 1. Goals & Summary

PingBack v0.2 evolves PingBack from a Claude-specific attention notifier into a unified local attention layer supporting **Claude Code** and **Codex CLI** on both **Windows** and **macOS**. AGY support was removed from this release and deferred to a future milestone.

Key capabilities introduced in v0.2:

- Multi-agent adapter architecture (`claude`, `codex`).
- Multi-agent session tracking, event routing, and enhanced `pingback status` display.
- Cross-platform terminal focusing ("Return to Agent" notification actions).
- Granular notification & audio customization via configuration and CLI (`pingback config`).
- Strict preservation of v0.1 invariants: 100% local-only, zero-config default, platform isolation, and non-blocking failure isolation.

## 3. Technical Plan

### Module & Directory Structure

```text
src/
├── agents/
│   ├── adapter.ts           # Core AgentAdapter interface & registry
│   ├── claude/              # Existing Claude adapter & hooks
│   ├── codex/               # Codex adapter & event normalizer
├── core/
│   ├── event-types.ts       # Extended AgentType, AgentEvent definitions
│   ├── daemon.ts            # Daemon lifecycle, multi-agent event routing
│   └── router.ts            # Attention routing & dispatch
├── sessions/
│   ├── session-types.ts     # Extended AgentSession schema (terminal info, status)
│   └── session-store.ts     # Multi-agent session persistence & isolation
├── notifications/
│   ├── notification-types.ts
│   ├── notification-policy.ts # Event-level customization rules
│   └── notifier.ts          # Desktop toast dispatch with actions
├── platform/
│   ├── platform-interface.ts
│   ├── windows/             # Windows toast, audio, and window focusing
│   └── macos/               # macOS toast, audio, and window focusing
└── cli/
    ├── commands/
    │   ├── setup.ts         # Multi-agent detection & setup
    │   ├── status.ts        # Multi-agent grouped status output
    │   └── config.ts        # Notification preference management
```

### Architectural Decisions & Invariants

1. **Agent-Agnostic Core**: Daemon, router, sessions, and notification engine operate exclusively on normalized models.
2. **Platform Abstraction**: All OS-specific code (Windows PowerShell/Win32 APIs vs macOS osascript/AppleScript) stays behind platform interfaces.
3. **Failure Isolation**: An unavailable or broken agent integration never degrades other active agent adapters or core notifications.
